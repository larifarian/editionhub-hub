HASE

Historical Activity and Source Exchange — ein offenes Austauschformat für historische Handlungen und Quellen

Was ist HASE?

HASE (Historical Activity and Source Exchange) ist ein Austauschformat für historische Handlungen und Quellen. Für den Datentransfer mit EH:historia ist HASE in zwei Formaten implementiert: XML (TEI) und JSON. So können Digitale Editionen und andere digitale Ressourcen ihre Daten unkompliziert in EH:historia einbringen.

HASE modelliert historische Handlungen (Activities) und die Quellen (Sources), die sie bezeugen: Briefkorrespondenz, Begegnungen, Reisen, Übernachtungen, Lektüre und mehr — aus Briefeditionen, Tagebüchern und anderen edierten Quellen.

Designprinzipien

EinfachEine Datei (XML (TEI) oder JSON) pro Projekt — wenige Pflichtfelder
ZweigeteiltHandlungen (was ist passiert?) + Quellen (woher wissen wir das?)
ErweiterbarEigene Handlungs- und Quellentypen vorschlagen
NormdatenNormdaten für Entitäten — automatische projektübergreifende Verknüpfung
ZweisprachigLabels und Beschreibungen in Englisch und Deutsch
CIDOC-CRMBasiert auf CIDOC-CRM — dem internationalen Standard für Kulturerbe

Daten einreichen

1

HASE-Datei erstellen

Wahlweise als JSON oder TEI/XML — beide Formate sind gleichwertig. Kopieren Sie das Minimalbeispiel und passen Sie es an. Nutzen Sie GND-IDs für Personen und Orte, wo möglich.

2

Datei bereitstellen

Entweder lokal auf Ihrem Rechner halten (für einmaliges Einreichen) oder an einer stabilen URL hosten (eigener Server, GitHub, Zenodo). Bei stabiler URL ist regelmäßige Übernahme per Harvesting möglich.

3

Einreichen

Auf der Einreichungs-Seite Liefer-Modus wählen (einmalig oder regelmäßig), Datei oder URL angeben, Kontaktdaten ergänzen. Wir prüfen, validieren und übernehmen.

Minimalbeispiel

Die einfachste gültige HASE-Datei — ein Projekt mit einer einzigen Briefsendung:

JSON

{
  "$schema": "https://editionhub.org/hase/schema/0.1",
  "@context": "https://editionhub.org/hase/context/0.1",
  "hase": "0.1",
  "project": {
    "id": "mein-projekt",
    "title": "Mein Forschungsprojekt"
  },
  "activities": [
    {
      "id": "brief-001",
      "type": "LETTER_SENDING",
      "date": "1786-09-03",
      "person": { "label": "Goethe, Johann Wolfgang von", "ref": ["gnd:118540238"] },
      "place": { "label": "Karlsbad", "ref": ["gnd:4029702-0"] }
    }
  ]
}

XML (TEI)

<?xml version="1.0" encoding="UTF-8"?>
<TEI xmlns="http://www.tei-c.org/ns/1.0">
  <teiHeader>
    <fileDesc>
      <titleStmt><title>Mein Forschungsprojekt</title></titleStmt>
      <publicationStmt><idno type="hase">mein-projekt</idno></publicationStmt>
      <sourceDesc><p/></sourceDesc>
    </fileDesc>
    <profileDesc><abstract>
      <listEvent>
        <event xml:id="brief-001" ana="#LETTER_SENDING">
          <desc>
            <date when="1786-09-03"/>
            <persName ref="gnd:118540238">Goethe, Johann Wolfgang von</persName>
            <placeName ref="gnd:4029702-0">Karlsbad</placeName>
          </desc>
        </event>
      </listEvent>
    </abstract></profileDesc>
  </teiHeader>
  <text><body><p/></body></text>
</TEI>

Datenmodell

HASE strukturiert Daten in drei Bereichen — unabhängig vom Format (XML (TEI) oder JSON):

1. Metadaten

Projekt-ID, Titel, URL, Lizenz, Kontakt — und optional eine Untergliederung in Editionen.

2. Daten

Handlungen

Historische Einzelhandlung — jede Handlung hat höchstens eine Person, einen Ort und ein Datum (mindestens eines davon). Verknüpft über Zusammenhänge (Korrespondenz, Reise, Begegnung) und Verkettung (vorher/nachher).

Quellen

Überlieferte Dokumente, die Handlungen bezeugen — Briefe, Tagebücher etc. Mit Archiv, Signatur, IIIF und Editions-URL.

Verarbeitung

EditionHub verarbeitet HASE-Dateien automatisch: 

HASE-Datei (XML (TEI) oder JSON)
    |
    +-- Validierung (RelaxNG / JSON-Schema)
    |
    +-- Normdaten-Aufloesung
    |       GND --> EditionHub-Index (automatischer Match)
    |       Neue Personen/Orte --> Vorschlag zur Aufnahme
    |       Koordinaten aus GeoNames ergaenzen
    |
    +-- RDF-Generierung (CIDOC-CRM)
    |       Activity --> crm:E7_Activity
    |       Actor    --> crm:P14 carried out by + owl:sameAs
    |       Place    --> crm:P7 took place at
    |       Thing    --> crm:P16 used specific object
    |       Source   --> crm:E31 Document + crm:P70 documents
    |
    +-- Upload nach RDF4J
            --> Live auf EditionHub
